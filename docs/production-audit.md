# Gracemark production-readiness audit

## Initial findings, before repairs

Scope: 419 tracked files on main at intake, including 69 Next pages, 107 API routes, three role layouts, shared libraries, styling, public assets, Supabase scripts, finance and backup workflows. No production student or financial records were used for testing.

| Severity | Finding and evidence | Initial disposition |
| --- | --- | --- |
| Critical | `api/auth/sync-profile` accepts a body auth ID without proof of possession, returns the corresponding profile, trusts user-editable metadata for roles and relinks students by email local part. | Confirmed in source. Owner requested report only. |
| Critical | The public identifier lookup can create a confirmed login with a shared password and rewrite account links and password-change flags during lookup. | Confirmed. Report only. |
| Critical | Migration 012 allows self-insert/update on users with a row identity check and table-level grants. Those checks allow choosing a privileged role unless another installed control prevents it. | Confirmed unsafe SQL; deployed grants/triggers unknown. Account-role changes are report only. |
| High | Admin device trust is a fixed cookie value. API authorization checks a bearer token and role without checking this second factor. OTP creation uses Math.random, stores the code directly and shares it across login and reset. View-only admins are restricted in navigation only. | Requires an approved authentication and database design spanning direct Supabase access. |
| High | Migration 013 allows students to select live result rows independent of publication. Migration 040 gates terminal snapshots but applies to a different table. | Prepare a restrictive policy locally and check existing readers. |
| High | Score save checks term permissions on submitted records only. Its delete-only path ignores locked terms and reports success after a database delete error. A matching term code unlocks an older session. Teacher scope can be inferred from caller-supplied context. | Repair save authorization, validate session and term and cover fixture denials. |
| High | The subject opt-out read endpoint accepts an unscoped list, and opt-out writes can remove results across the session. Class remark permissions omit the academic session. | Scope reads and mutations to authorized class, subject and session. |
| High | Two result-sheet workbooks ship in public/assets. Their URLs bypass all app and database controls. Repository visibility, historical releases and whether the sheets contain real pupils are unverified. | Preserve files and remove public serving. |
| High | The shared offline queue can replay one staff member's pending scores or attendance with another account's token. | Bind replay to the originating user. |
| High | Publishing, promotion and opt-out each perform multiple database writes. A failure or concurrent edit can leave only part of a change applied. Manual payments use a new reference per request, including retries. | Verify in isolated PostgreSQL before transaction or ledger migrations. |
| Medium | The shared drawer uses different desktop breakpoints for resize and layout. Closed drawer links can receive keyboard focus. Rankings repeatedly scan the entire class for each student. | Correct navigation and preserve ranking ties while reducing work. |
| Medium | The lint script invokes the removed Next lint command. Setup guidance describes a previous app. | Run validation, repair where feasible, and record remaining deployment work. |

Repair order: protect result data and files, then address authorization and integrity, correct navigation, reduce repeated queries and ranking work, remove verified debris, run fixtures/type/lint/build/dependency checks and record residual risks. The actual Supabase policies, deployment visibility, gateway settings, backup access and browser/device behavior require independent verification.

## Release decision

**Hold production release.** The critical profile-sync, shared-password provisioning and database role-escalation findings remain open at the owner's request. A user who can obtain an administrator role can defeat checks that otherwise correctly limit students and teachers. The fixes below are local, with migrations tested against disposable fixtures. They do not establish the configuration of the hosted portal.

## Findings addressed locally

| Severity | Location and root cause | Repair and evidence |
| --- | --- | --- |
| High | Public web assets included two result-sheet workbooks. | Moved both intact to the project root and compared SHA-256 hashes. Check old Vercel deployment URLs, repository visibility and copies independently. A local move cannot recall past downloads. |
| High | Attendance GET and POST used the service role after checking only the caller's role. Remark checks omitted session. The current class roster could also be backfilled into an earlier session. | Attendance and evaluation routes check class-teacher assignment for the requested session. Legacy direct class assignments are valid for the current session only. Historical attendance uses the recorded enrollment. Fixture checks deny a teacher reading or writing another class. |
| High | Score saves trusted assignment context and client-supplied grades. Term checks skipped deletions and could mistake last year's first term for this year's. | Resolve the session by its stored name, validate all targets before writing, scope the roster by session and check one assignment per sheet. Calculate component scores and grade on the server using the existing engine. Reject invalid or empty breakdowns. Test fixtures include forged grades, an explicit zero, a foreign pupil, a mismatched session and locked-term deletions. |
| High | Deleting scores and saving the rest were separate requests. Legacy rows without breakdowns appeared empty to the editor. | Migration 043 performs the batch in one database transaction and rechecks deletion context and publication under row locks. The editor skips blank legacy aggregate-only rows. A failing insert in the PostgreSQL fixture rolled back the preceding deletion. Admin edits preserve teacher attribution. |
| High | Students could read draft scores through permissive SQL. Teachers could list opt-outs outside their assignment. | Migration 042 restricts direct score reads and removes direct client score writes. The opt-out API scopes a teacher's roster and checks affected terms before removing scores. Direct authenticated opt-out access is restricted to admins. SQL tests exercised a deliberately broad pre-existing policy. |
| High | Offline queues were shared between signed-in accounts. | New saves use a per-user queue. Replay uses the same session for queue selection and authorization. Temporary server errors keep the item queued. Existing unowned v1 entries are left on the device and never automatically attributed; the originating teacher must reconcile any outstanding older changes. Browser storage still contains pending academic data on the device. |
| High | A retried manual payment could create a second successful transaction and receipt. | The admin form reuses a request key when retrying the same entry. The API uses the unique payment reference and returns the original receipt when the invoice, amount, method, notes and collector match. A changed request with the same key receives 409. The fixture recorded exactly one transaction. Older callers without a key and a newly opened form remain separate payments. |
| High | Publication and promotion can succeed partially. Promotion accepted the same source and destination session. | The promotion endpoint now refuses identical or unresolved session IDs and reports a history-write failure. Report construction propagates failures checking settings and enrollments. **Partial remediation:** full publication, promotion/rollback and opt-out operations still need transactional integration testing across the deployed schema. |
| Medium | Gradebook fallbacks dropped the session filter, and summaries discarded actual zeroes. The student report header showed the current class after promotion. | Scope staff assignments, live results, legacy fallback rows and snapshots to the selected session. Keep null scores blank and include recorded zeroes in descriptive statistics. Resolve the displayed class from the selected enrollment. The student route fixture checks the historical class. |
| Medium | The admin backup could stop at the database API row cap and silently replace failed tables with empty arrays. | Page through the configured tables in stable key order, propagate query failures and retain the existing user-field allowlist. This is an application export; verify a restore and large-export response limits independently. |
| Medium | Shared sidebar resize and visibility logic disagreed on tablets. The splash remover modified a node owned by React. | Align the desktop breakpoint, hide closed drawer links from keyboard navigation, expose expanded/current state and let React own the splash transition. Also corrected misleading empty-week copy. |
| Medium | Each score save ran an assignment query per pupil; rankings counted every higher score separately for every pupil; student report reads loaded every full snapshot in a session. | One assignment lookup per sheet, sorted competition ranking with gaps for ties, a lightweight term index and selected-term payloads only. Students do not fetch terminal-result payloads through the ordinary report query. All API responses have a private/no-store header in Next configuration. |
| Low | Deprecated lint command, stale setup instructions and an empty tracked file. | Installed development lint tools, patched their vulnerable file-matching dependency and corrected the README. Removed the zero-byte, unreferenced `tatus` file; recoverable from Git. No database backup, migration or academic workbook was deleted. |

## Required owner actions and remaining risks

1. The owner requested report-only handling for account repair, public login provisioning and account-role protections. The release blocker remains open. Have an authorized maintainer test self-registration, metadata roles, forged body auth IDs, peer reads, self-role updates and login recovery against staging. Review the static admin device cookie, OTP reuse/rate limits, API enforcement and view-only administrator permissions together.
2. Compare the deployed schema with the [policy inventory](database-policy-inventory.md). The repository contains alternative baselines and historical permissive scripts. Replaying the complete directory is unsafe. Validate `042_result_access.sql` and `043_save_score_sheet.sql` on a representative staging copy before the app release. **Score entry requires 043.** The in-memory database tests establish migration behavior with synthetic tables, not parity with every legacy installation.
3. Verify publishing, recall, opt-out and promotion/rollback under concurrent edits and injected failures in staging. Some paths issue multiple writes or ignore individual database errors. Check the scheduled backup and restore path and retention/access for GitHub Actions artifacts. A service-role JSON export can contain sensitive records.
4. Establish who could access the older workbooks and whether they contain real records. Inspect public asset caches, older deployments, source history and backups through approved school channels. Repository history was preserved.
5. Confirm online fee and scratch-card switches separately. Reconcile the school's explicit-zero and missing-score policies, run a historical report for a promoted test student and test printing populated multi-page reports on the school's actual paper/printer.
6. Recheck Auth/session revocation, offline work recovery, public email/identifier enumeration and direct database access using separate role sessions. Offline data on shared devices, the legacy snapshot policies and public verification functions deserve specific checks.

The authorization review follows the object-by-object checks described by [OWASP API1](https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/). Database and build references: [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security) and [Next.js ESLint](https://nextjs.org/docs/app/api-reference/config/eslint).
